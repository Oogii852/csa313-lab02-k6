Baseline (5 VU) p95 нь 357.58ms тул SLO-г baseline x 1.5 = p(95)<537 мс, error rate < 1% гэж тогтоов. Baseline-аас 1.5 дахин зайтай сонгосон нь жирийн сүлжээний хэлбэлзлийг зөвшөөрч, бодит удаашралыг илрүүлэх хэмжээ юм.

- 30 VU, p(95)<537: нийцсэн (PASS), results/threshold-pass.txt (гарах код 0)
- 30 VU, санаатайгаар хатуу p(95)<50: FAIL, results/threshold-fail.txt (гарах код 99)

## Дүгнэлт

5, 30, 100 VU гурван түвшинд тус тусад нь 1 минут ажиллуулахад p95 latency 357.58ms, 358.26ms, 287.58ms болж, 5 VU-тэй харьцуулахад 100 VU дээр буурсан. Throughput 7.373154/s, ..., 144.800589/s болж, 5 VU-тэй харьцуулахад 100 VU дээр өссөн; sleep(1) байгаа тул VU бүр секундэд ойролцоогоор 1 хүсэлт илгээдэг. Error rate 0.00%, 0.00%, 0.00% байв. Хэмжсэн түвшин бүрд p95 нь baseline-ийн 1.5 дахиас (537 мс) хэтрээгүй тул хэрэглэгчийн туршлага муудсан тодорхой цэг ажиглагдсангүй. Дундажаас p95 нь урт сүүлийн (tail) latency-г илүү сайн илрүүлдэг, учир нь цөөн удаан хүсэлт дунджид нуугддаг. Лекцийн throughput, latency, error rate хэмжүүрүүдийг бодитоор тусад нь хэмжиж, http_req_failed нь POFOD-ийн аналог болохыг харав. SLO-г baseline p95 357.58ms x 1.5 = 537 мс, error rate < 1% гэж тогтоов. 30 VU-ийн ажиллуулалт энэ SLO-д нийцсэн (PASS), харин санаатайгаар хатуу болгосон p(95)<50 threshold нь FAIL болсон нь CI pipeline-ий quality gate-тэй ижил зарчим. Stages нь нэгтгэсэн ганц summary өгдөг тул хүснэгтийг тусдаа ажиллуулалтуудаас гаргав. Гадаад сайт руу тест хийсэн тул сүлжээний хэлбэлзэл үр дүнд нөлөөлсөн байж болно.
